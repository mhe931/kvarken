\section{Source selection and attribution}

The single case study uses an overlapping Sentinel-1 and Sentinel-2 observation pair that
was available as analysis-ready raster assets for a reproducible, local application. The
Sentinel-1 acquisition was made on 30 March 2021 at 16:06:12 UTC. The Sentinel-2 acquisition
was made on 31 March 2021 at 10:00:21 UTC, 17.90 hours later. The records were selected to
exercise the end-to-end workflow; the selection was not a temporal sample or a claim of
representativeness. This acquisition mismatch permits changes in surface conditions between
observations and limits the optical comparison.

ESA supplied the Sentinel satellite observations. The Sentinel-1 raster is an upstream
CATALYST radiometric terrain-correction (RTC) product. Microsoft Planetary Computer hosted
and distributed the STAC records and Cloud-Optimized GeoTIFF assets used for spatial-window
access. The analysis relies on the upstream gamma-zero RTC processing; it does not claim to
have independently run or verified that processor's version, thermal-noise treatment or
border-noise treatment. This source permits the thesis to separate upstream radar processing
from its own reprojection, masking, optical-proxy construction, classification, evaluation
and plotting. It demonstrates a scientific application, not the CDSE pixel-download path.
The collection and product documentation used to identify the RTC, Sentinel-2 processing
and WorldCover source roles is cited here \citep{pc-s1-rtc,s2-processing,worldcover2021};
the recorded provider roles and licenses are retained in
\texttt{docs/research/20261019/source\_licenses.json}.

ESA WorldCover 2021 v200 supplies the static land-cover mask. It is an annual, retrospective
land-cover product and is not a contemporaneous March 2021 ice observation or validation
reference. The four selected tiles screen mapped land; they do not classify ice.

\section{Recorded processing parameters}

The following values are taken from \texttt{docs/research/20261019/case\_config.json},
the retained run records and the implementation:

\begin{itemize}
\item Study rectangle: \([20.5,62.8,22.5,63.8]\) in EPSG:4326; analysis grid: EPSG:32634
  at 100~m resolution.
\item Mapped-water threshold: fraction \(\geq0.999999\); retain the largest eight-connected
  water component; apply a 300~m square coastal erosion.
\item Sentinel-2 reflectance quantification factor: 10,000 for the recorded N0212 products.
  Resample reflectance by averaging and categorical SCL/WorldCover with nearest neighbour;
  native-resolution class fractions supply the purity screening.
\item Optical dark-water proxy: SCL class 6, near-infrared \(<0.04\), green \(<0.10\).
  Snow-covered-ice proxy: SCL class 11, green \(>0.15\), near-infrared \(>0.10\), and
  \(\mathrm{NDSI}>0.4\). Require at least 99\% native SCL class purity for each label.
\item Classifier: linear discriminant using VV and VH, equal class priors and 5\% isotropic
  covariance shrinkage; no held-out tuning.
\item Spatial evaluation: 10,000~m blocks with a 1,000~m edge exclusion. Report all
  held-out blocks, including single-class blocks.
\end{itemize}

The acquisition and quality-mask manifests preserve source item identifiers, processing
roles, asset names, resampling and checksums. Hashes identify retained reprojected windows;
they do not identify complete original SAFE packages. Large raster windows are excluded from
Git and must be acquired again for a clean checkout. Do not copy signed URLs or credentials
into source, reports or shell history.

\section{Scientific and engineering evidence}

The actual one-case comparison reports ice precision of 23.53\%, ordinary agreement of
88.00\%, and 95.99\% ordinary agreement for the always-water baseline on the same held-out
cells. The modelled candidate ice area is 1,219.28~km$^2$; 795.91~km$^2$ of candidate area
has no optical proxy label. The full candidate area is not validated sea-ice extent. These
figures describe agreement with selected Sentinel-2 proxy labels, not field accuracy.

The CSC project 2021696 demonstration processed five authentic captured scene-metadata
records through provenance storage, SQLite catalog persistence, Kvarken regional queries
and a loopback API. The saved evidence records zero failures and retries, elapsed timings,
source identity and checksums. Raster classification ran locally; CSC did not perform
satellite-image classification, large-scale raster processing, distributed execution or
GPU acceleration.

The frozen 256-scene benchmark is synthetic and remains unchanged. Its legacy recovery-ratio
value of 1.000000 is retained as a reporting convention. Because that run observed zero
failures and retries, recovery was not measured (N/A); fault-injection tests provide the
recovery evidence. The 20260915 report is an offline fallback using fixtures, not a live
CDSE experiment. CDSE OAuth2/STAC metadata interfaces are covered by offline tests; no
successful live CDSE metadata request or CDSE pixel download is confirmed. A previously
recorded unauthenticated CDSE raster request returned HTTP 401.

\section{Clean-checkout reproduction}

These commands are written for PowerShell from a directory in which the repository is to be
created. The package supports Python 3.11 and later; the verified local scientific run used
Windows 11, Python 3.12.15, NumPy 2.5.4, Rasterio 1.5.2, GDAL 3.12.2, Matplotlib 3.11.2
and SciPy 1.18.1. The CSC metadata demonstration used Ubuntu 24.04.5 and Python 3.12.3.
No command in this appendix was run to reacquire the satellite data during this revision.

\subsection{Clone and create a Python environment}

\begin{verbatim}
git clone https://github.com/mhe931/kvarken.git
Set-Location kvarken
python -m venv .venv
.\.venv\Scripts\Activate.ps1
\end{verbatim}

\subsection{Install dependencies}

The core runtime is standard-library-only. Install development and scientific extras for the
full test suite and raster case study:

\begin{verbatim}
python -m pip install -e ".[dev,science]"
\end{verbatim}

The optional Word exporter also requires the \texttt{documents} extra, Pandoc, the official
University of Vaasa DOTX template, and the APA CSL file. Those external files are not included
in Git; their official sources and the export command are documented in
\texttt{thesis/README.md}.

\subsection{Run tests and offline checks}

Each line below is a separate command. Success means the process exits with status zero; test
counts may change as tests are added.

\begin{verbatim}
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m kvarken_eo verify-health
\end{verbatim}

\subsection{Acquire fresh source data}

The following command performs fresh source acquisition and scientific analysis. It requires
network access to Microsoft Planetary Computer. Both the input and output directory paths must
be new and absent before the command runs. The large raster windows are not in Git; this step
is necessary on a clean checkout.

\begin{verbatim}
python -m kvarken_eo.case_study --config docs\research\20261019\case_config.json --inputs-dir data\seaice_reproduction --output-dir outputs\seaice_fresh_20261022
\end{verbatim}

The expected success indicator is exit status zero and a populated output directory including
\texttt{results.json}, georeferenced outputs, figures, and acquisition/provenance records.
The command's exact supported options are printed by
\texttt{python -m kvarken\_eo.case\_study --help}. Use
\texttt{--resume-acquisition} only to continue an interrupted acquisition with the same
configuration. \texttt{--prepare-quality-masks} is for an older cache missing its supplemental
native-resolution masks; it is not required for a fresh acquisition.

\subsection{Reuse previously captured data and generate a report}

Previously captured raster inputs are not tracked in Git. Copy a complete, checksum-verified
input cache from a retained local archive into
\texttt{data\textbackslash{}seaice\_reproduction}; if that archive is unavailable, run the fresh-acquisition command
above. The cache directory must exist and contain the complete verified inputs. Reuse does not
reacquire pixels; it creates a new scientific report and figures in a distinct output directory
that does not yet exist:

\begin{verbatim}
python -m kvarken_eo.case_study --inputs-dir data\seaice_reproduction --output-dir outputs\seaice_reused_20261022 --reuse-inputs
\end{verbatim}

This command validates cached hashes, processes the captured data and writes a new
\texttt{results.json} and figures. It does not overwrite the frozen benchmark, the 20260915
offline-fallback artifact, or the recorded 20261019 actual-data evidence. The CLI requires
both \texttt{--inputs-dir} and \texttt{--output-dir}; the correct option spelling is
\texttt{--output-dir}. A reuse run is successful only when its input checks pass and its
reported source/configuration identities match the intended cache.

\subsection{Build the LaTeX manuscript}

With XeLaTeX, Biber, and the listed TeX packages installed, run each command from the
\texttt{thesis} directory. The final two XeLaTeX passes resolve the table of contents,
figure/table lists, page numbers, and cross-references.

\begin{verbatim}
Set-Location thesis
xelatex -interaction=nonstopmode -halt-on-error main.tex
biber main
xelatex -interaction=nonstopmode -halt-on-error main.tex
xelatex -interaction=nonstopmode -halt-on-error main.tex
\end{verbatim}

The CI smoke build uses Ubuntu 24.04, XeLaTeX, Biber and Carlito when Calibri is unavailable.
The local review manuscript uses the installed Calibri font when present. A successful build
does not establish independent PDF/A conformance, PDF accessibility, author approval,
supervisor acceptance or submission authorization.
